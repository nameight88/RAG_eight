# Phase 1: 파싱 최적화 + 메타데이터 강화 임베딩 설계

**작성일:** 2026-03-24
**프로젝트:** RAG_eight — 금융감독원 문서 RAG 시스템
**목표:** 날짜 파싱 정규화 및 메타데이터 기반 검색 품질 개선

---

## 1. 문제 정의

### 1.1 날짜 파싱 불일치

현재 크롤러가 수집하는 날짜 형식이 7가지로 혼재되어 있음:

| 형식 | 예시 | 건수 |
|------|------|------|
| `YYYY.MM.DD` | `2016.06.16` | 41건 |
| `YYYY. M. DD` | `2016. 1. 22` | 23건 |
| `YYYY. M. D` | `2014. 1. 7` | 20건 |
| `YYYY. MM. DD` | `2016. 11. 22` | 6건 |
| `YYYY. MM. D` | `2016. 11. 7` | 1건 |
| `YYYY.M.DD` | `2014.1.15` | 1건 |
| 기타 | — | — |

현재 변환 로직 `re.sub(r'[^\d]', '', date)[:8]` 는 단일 자릿수 월/일(`2014.1.7`)을 `201417`(6자리)로 잘못 처리함.

### 1.2 검색 품질 불량

- 벡터 청크에 날짜·기관·문서유형 메타데이터가 없거나 비정규화 상태
- 날짜 기반 필터링 불가 (예: "2023년 이후 제재 건만 검색")
- 기관명 필터링 불가

## 2. 설계

### 2.1 날짜 정규화 모듈 (`date_normalizer.py`)

신규 파일로 단일 책임 원칙에 따라 날짜 정규화만 담당.

**입력:** 임의 형식의 날짜 문자열
**출력:** `YYYY-MM-DD` 형식 문자열 또는 `None`

```
정규화 우선순위:
1. 숫자만 추출 후 자릿수 기반 파싱 (YYYYMMDD → 8자리 보장)
2. 점/공백 분리 후 연/월/일 각각 zero-padding
3. 실패 시 None 반환 (빈 문자열 대신 명시적 None)
```

**지원 입력 패턴:**
- `YYYY.MM.DD`, `YYYY.M.D`, `YYYY. MM. DD`, `YYYY. M. D` 등 모든 변형
- `YYYY년 MM월 DD일` 한글 형식 (향후 대비)

### 2.2 크롤러 수정

**대상 파일:**
- `fss_crawler_management_eight.py`
- `fss_crawler_section_eight.py`

**변경 내용:**
- 날짜 저장 시 `date_normalizer.normalize_date()` 호출
- 정규화 실패 시 `None` 저장 (기존 오류 은닉 방지)
- `date_str` 생성 로직을 정규화된 날짜 기반으로 교체

### 2.3 청커 메타데이터 강화

**대상 파일:**
- `adaptive_chunker.py`
- `semantic_chunker.py`

**추가 메타데이터 필드:**

| 필드 | 타입 | 설명 |
|------|------|------|
| `date` | `str` (YYYY-MM-DD) | 정규화된 날짜 |
| `institution` | `str` | 기관명 |
| `doc_type` | `str` | `경영유의사항` 또는 `제재결과` |
| `year` | `int` | 연도 (쿼리 편의성용) |
| `month` | `int` | 월 (쿼리 편의성용) |

**이유:** FAISS는 메타데이터 필터를 Python 레벨 후처리로 구현하므로 정수/문자열 성능 차이는 없음. 다만 날짜 범위 필터 작성 편의성을 위해 `year`, `month`를 별도 저장. ChromaDB 사용 시에는 `where` 절 정수 비교 이점도 추가로 존재.

### 2.4 RAG 시스템 검색 개선 (`rag_system.py`)

**추가 기능:**
- `search()` 함수에 `date_from`, `date_to`, `institution`, `doc_type` 선택적 파라미터 추가
- ChromaDB `where` 절 또는 FAISS 후처리 필터로 메타데이터 필터링 적용
- 필터 미입력 시 기존 동작과 동일 (하위 호환 유지)

**기존 `preprocess_query` 자동 필터와의 우선순위 규칙:**
- 현재 `rag_system.py`의 `preprocess_query()`는 질의 텍스트에서 날짜/기관을 자동 추출하는 로직이 존재함
- 명시적 파라미터(`date_from`, `institution` 등)가 전달된 경우 **명시적 파라미터가 우선 적용**
- 명시적 파라미터가 `None`인 경우에만 `preprocess_query` 자동 추출 결과 사용
- 이를 통해 API 호출자가 필터를 직접 제어할 수 있으며 자동 추출과 충돌하지 않음

---

## 3. 데이터 흐름

```
크롤러 수집
    → date_normalizer.normalize_date(raw_date) → "YYYY-MM-DD"
    → JSON 저장 (정규화된 date 포함)
    → 청커에서 청크 생성 시 메타데이터 {date, institution, doc_type, year, month} 첨부
    → 벡터 DB 임베딩 저장
    → 검색 시 메타데이터 필터 + 벡터 유사도 결합
```

## 4. 에러 처리

| 상황 | 처리 방법 |
|------|-----------|
| 날짜 파싱 완전 실패 | `None` 저장, 로그 출력, 크롤링 중단 없음 |
| 메타데이터 누락 청크 | 필터 제외 대상으로 처리 (검색은 가능) |
| 기존 벡터 DB 재색인 | 청커 재실행으로 전체 재빌드 필요 (1회성) |

---

## 5. 테스트 기준

- `date_normalizer` 단위 테스트: 7가지 입력 형식 모두 `YYYY-MM-DD` 반환 확인
- 기존 JSON 파일 전체 날짜 재정규화 후 `None` 건수 측정 및 기록 (HTML에 날짜가 누락된 문서가 있을 수 있으므로 0 보장 목표가 아닌 현황 파악이 목적)
- 메타데이터 필터 검색: 날짜 범위 + 기관명 필터 결합 쿼리 정상 동작 확인
